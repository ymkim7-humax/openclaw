Project: airoha/2025q3 | Owner: Chunsu Lim(임춘수)
이 패치에 대한 코드 리뷰 결과입니다. `MAX_SSID_NUMBER`를 `MAX_BINDING_SSID_COUNT`로 변경하는 과정에서 몇 가지 확인이 필요한 사항과 잠재적인 문제가 발견되었습니다.
상세 리뷰 보기 #### 1. `MAX_BINDING_SSID_COUNT` 정의의 적절성 (`hal_wifi.h`) ```cpp +#define MAX_BINDING_SSID_COUNT SSID_ID_5G_GUEST3 ``` * **문제점:** 일반적으로 `SSID_ID_5G_GUEST3`가 Enum의 마지막 항목을 나타내는 인덱스라면, 배열의 크기나 루프의 한계값으로 사용할 때 **총 개수(Count)**가 맞는지 확인해야 합니다. 만약 Enum이 0부터 시작한다면 실제 개수는 `SSID_ID_5G_GUEST3 + 1`이 되어야 할 가능성이 높습니다. * **권장 사항:** `SSID_ID_5G_GUEST3`의 정의를 확인하여, 배열 크기로 사용하기에 충분한 값인지(OOB: Out Of Bounds 발생 여부) 확인하십시오. 보통 `MAX_..._COUNT`는 실제 개수를 의미하도록 정의하거나 `LAST_ENUM_VALUE + 1`로 정의하는 것이 안전합니다. #### 2. `hal_params.h` 내의 무관한 정의 삭제 ```cpp -#define ATTR_DHCP_LAN_DHCPV6_PD "dhcpv6_pd" -#define ATTR_DHCP_LAN_RA_LIFETIME "ra_lifetime" ... -#define ATTR_DHCP_LAN_PREFIX_FILTER "prefix_filter" -#define ATTR_DHCP_LAN_LINK_AGGREGATION "link_aggregation" ``` * **문제점:** 패치의 주제인 `MAX_BINDING_SSID_COUNT`와 관련이 없어 보이는 DHCP 및 Link Aggregation 관련 매크로들이 삭제되었습니다. * **확인 필요:** 이 매크로들이 실제로 프로젝트 전체에서 더 이상 사용되지 않는 것인지, 아니면 실수로 삭제된 것인지 확인이 필요합니다. 만약 다른 작업의 일부라면 커밋을 분리하거나 이유를 명시해야 합니다. #### 3. 헤더 의존성 확인 * `MAX_BINDING_SSID_COUNT`는 `hal_wifi.h`에 정의되어 있습니다. * 이 매크로를 사용하는 `hal_network.h`, `wa_publish_api.cpp`, `wa_set_api.cpp`, `FalNetwork.cpp` 등에서 `hal_wifi.h`가 적절히 include 되어 있는지 확인이 필요합니다. 기존에 `hal_params.h`를 참조하던 곳들이 `hal_wifi.h`를 직접 참조하지 않아 빌드 에러가 발생할 수 있습니다. #### 4. 데이터 정합성 (기존 설정값과의 호환성) * `MAX_SSID_NUMBER`는 기존에 `8`로 정의되어 있었습니다. * `MAX_BINDING_SSID_COUNT` (`SSID_ID_5G_GUEST3`)가 8보다 작아질 경우, 기존에 저장된 설정(Config)에서 8번 SSID 등에 접근하려 할 때 데이터 유실이나 루프 범위 축소로 인한 오동작이 발생할 수 있습니다. * 반대로 8보다 커질 경우, 기존의 고정된 크기의 버퍼나 DB 스키마와 충돌이 없는지 검토해야 합니다. ### 요약 `MAX_BINDING_SSID_COUNT`의 실제 숫자 값이 배열 크기와 루프 조건에 부합하는지(Index vs Count) 재확인하시기 바라며, `hal_params.h`에서 삭제된 무관한 매크로들에 대한 의도적인 삭제 여부를 검토해 주시기 바랍니다.

[ARHT-45] hal_unify: tcp, upd, tcp/udp
Feedback
Project: airoha/2025q3 | Owner: Chunsu Lim(임춘수)
I have analyzed the Gerrit patch and found several issues that need to be addressed. While the general unification of protocol strings is a good direction, there are inconsistencies, typos, and potentially breaking changes.
Detailed Review ### 1. Typo in Commit Message The subject line contains a typo: `upd` should be `udp`. - **Current:** `[ARHT-45] hal_unify: tcp, upd, tcp/udp` - **Recommended:** `[ARHT-45] hal_unify: tcp, udp, tcp/udp` ### 2. Unexplained Removal of VLAN Attributes In `hal_params.h`, the following macros were removed: ```cpp -#define ATTR_WAN_VLAN_DEI "vlan_dei" -#define ATTR_WAN_VLAN_TPID "vlan_tpid" ``` These removals seem unrelated to the unification of protocol strings (TCP/UDP). If these attributes are still used in other parts of the codebase, this change will cause compilation errors. If they are truly deprecated, this should be mentioned in the commit message or handled in a separate "cleanup" task. ### 3. Inconsistent Logic in `HalService_getPortForwarding` In `hal_service.c`, the refactoring of the configuration retrieval logic is inconsistent: ```cpp + if (HalConfig_get(nodeName, OPTION_ENABLED, active, sizeof(active)) != HAL_SUCCESS || + HalConfig_get(nodeName, OPTION_PROTOCOL, protocol, sizeof(protocol)) != HAL_SUCCESS || + ... + HalConfig_get(nodeName, OPTION_SERVICE_TYPE, serviceType, sizeof(serviceType))) // <-- Missing != HAL_SUCCESS ``` The last condition is missing `!= HAL_SUCCESS`. While it might evaluate to "true" on failure (assuming `HAL_SUCCESS` is 0 and failure is non-zero), it is inconsistent with the preceding lines and makes the code harder to maintain. ### 4. Code Cleanup Opportunity in `HalService_getPortForwarding` The refactored block in `HalService_getPortForwarding` has a logic change: - **Original:** Checked if all `HalConfig_get` calls succeeded before proceeding. - **New:** Returns `HAL_FAILURE` if any call fails. This is a good improvement in terms of readability (reducing indentation), but ensure that the remaining logic (setting `pstPortMapping` fields) is only reached when all config gets are successful. The current implementation correctly does this, but the inconsistency mentioned in point #3 should be fixed. ### Summary of Recommended Actions 1. Fix the typo in the commit subject. 2. Verify if `ATTR_WAN_VLAN_DEI` and `ATTR_WAN_VLAN_TPID` are still needed. If not, explain their removal in the commit message. 3. Add `!= HAL_SUCCESS` to the last condition in the `if` statement within `HalService_getPortForwarding`.
