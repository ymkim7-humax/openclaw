Feedback ### 1. 보안성 향상 (긍정적) * **비밀번호 노출 방지:** 기존 코드에서 `AdminPassword`와 `SuperAdminPassword`를 조회할 때 실제 값을 반환하거나 기본값(`aisadmin`, `fibre...`)을 반환하던 것을 빈 문자열(`""`)로 변경한 것은 보안상 바람직합니다. * **TR-069 표준 준수:** CWMP(TR-069) 프로토콜에서 비밀번호 관련 파라미터는 보안을 위해 Get 요청 시 빈 문자열을 반환(Write-Only)하는 것이 일반적인 관례입니다. ### 2. 기술적 검토 및 개선 사항 * **비정상적인 문자열 제거:** 기존 코드의 `get_SuperAdminPassword`에 포함되어 있던 매우 긴 빌드 경로 및 파일 목록 문자열(`fibre @jobs/auto_build/...`)은 소스 코드에 포함되어서는 안 될 잘못된 데이터로 보입니다. 이를 제거한 것은 적절합니다. * **영향도 확인:** 이 스크립트가 ACS(CWMP) 전용인지, 아니면 내부의 다른 시스템에서도 사용되는지 확인이 필요합니다. 만약 다른 내부 로직에서 이 함수를 호출하여 실제 비밀번호를 가져와야 한다면 기능 장애가 발생할 수 있습니다. * **데이터 모델 정의와의 일치:** 해당 파라미터가 TR-098 또는 TR-181 데이터 모델 정의에서 `Write-Only`로 설정되어 있는지 확인하십시오. 단순히 빈 문자열을 반환하는 것보다, 데이터 모델 레벨에서 보안 속성을 정의하는 것이 더 근본적인 해결책입니다. ### 3. 커밋 메시지 보완 권고 * **'Fix the display values'의 모호성:** 커밋 메시지에서 "Display value를 수정한다"고만 되어 있는데, 구체적으로 "보안 강화를 위해 ACS 조회 시 비밀번호를 마스킹(빈 문자열 반환) 처리함"과 같이 의도를 명확히 기재하는 것이 좋습니다. ### 결론 보안 측면에서 올바른 방향의 수정이나, **이 함수를 내부적으로 호출하는 다른 컴포넌트가 없는지 최종 확인**이 필요합니다. 또한, 원본 코드에 왜 비정상적인 경로 문자열이 포함되어 있었는지에 대한 원인 파악이 병행되면 향후 유사 사례 방지에 도움이 될 것입니다.
