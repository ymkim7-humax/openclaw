[ARHT-312] cwmp: InternetGatewayDevice.X_AIS_UplinkSetup
REJECT
Project: airoha/2025q3 | Owner: [Marusys VINA] Jack
Feedback\n\n### Critical Security Issues\n* **Shell Injection Vulnerability:** The `uplink_set_handler` function in `uplink_obj.c` takes `ifname` and `mode` directly from UBUS and passes them to `system()` without any sanitization. An attacker could inject arbitrary commands (e.g., setting `interface` to `\"; reboot ;\"`).\n* **Unsanitized Shell Script:** The `uplink_setup.sh` script uses positional parameters `$INTERFACE`, `$MODE`, `$IP`, and `$MASK` directly in commands like `ifconfig` and `udhcpc`. This compounds the shell injection risk if the calling C code is bypassed or modified.\n\n### Code Quality Issues\n* **Debug Prints:** There is a leftover `printf(\"DEBUG: ...\")` in `uplink_obj.c`. This should be removed or replaced with proper logging (e.g., `syslog`).\n* **Insecure Execution:** Using `system()` is generally discouraged for system-level binaries. It is better to use `fork()` and `execv()` with a fixed argument list to prevent shell interpretation.\n* **Hardcoded Paths:** The script path `/apps/private/tr069/scripts/uplink_setup.sh` is hardcoded, which reduces portability.\n\n### Suggestions\n* Implement strict validation/whitelisting for `ifname` (e.g., regex `^[a-zA-Z0-9.]+ $`) and `mode` (e.g., only \"DHCP\" or \"Static\").\n* Replace `system()` with `execve()` to avoid spawning a shell.\n
