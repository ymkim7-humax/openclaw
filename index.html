[ARHT-138] Fix the issues of mesh topology.
Feedback
Project: airoha/2025q3 | Owner: [Marusys VINA] Karina
### Gerrit Patch Analysis Results 1. **`FalGateway.cpp` Potential Crash Hazard**: - The code `pstIntf[atoi(pDevList.devList[i].path) - 1]` contains a high risk of **Segmentation Fault (Crash)**. - If `path` is not a numeric string (e.g., "lan", "2.4g") or if the value is out of the bounds of `pstIntf` (0 or >= MAX_ETHERNET_PORT_NUMBER), an out-of-bounds array access will occur. - Specifically, for Wi-Fi connected devices, accessing the Ethernet port status array (`pstIntf`) using `path` as an index is logically incorrect. 2. **`dnstrap.c` Excessive Packet Capture**: - Adding `source port 53` to the DNS Trap targets causes all DNS response packets to be intercepted by the kernel. - In a bridge environment, this can lead to unnecessary CPU load and performance degradation. - Intercepting responses might be an over-implementation if the original goal was only to intercept DNS queries.
Detailed Feedback The current implementation lacks safety checks before array indexing and might introduce performance bottlenecks in high-traffic scenarios.

[ARHT-64] Implement On Top Easy Mesh
Feedback
Project: airoha/2025q3 | Owner: [Marusys VINA] Tien
### Gerrit Patch Analysis Results 1. **Massive Implementation of "On Top Easy Mesh"**: - The patch introduces a significant amount of new code across multiple components: `1905daemon`, `mapd`, `wappd`, `ledctrl`, and a new application `ontopmesh`. - This seems to be a vendor-specific EasyMesh extension for Humax. 2. **Potential Security and Stability Concerns**: - **`system()` calls**: Multiple occurrences of `system()` with string concatenation (e.g., `system("rm -f "OTMESH_DUMP_FILE_PATH)`) are present. This can be vulnerable to command injection if variables aren't strictly validated. - **`fork()` and `exit()`**: In `otmesh_applyWifiSetting`, a `fork()` is used to restart Wi-Fi settings. Ensure this doesn't lead to zombie processes or race conditions. - **File I/O in `/tmp`**: Extensive use of `/tmp` for IPC (`/tmp/otmesh_bh_ready`). Ensure file permissions are restrictive. 3. **Code Quality**: - **Dead Code**: Commented-out code in Makefiles should be cleaned up. - **Magic Numbers**: Hardcoded string lengths and indices should be replaced with constants.
Detailed Feedback - Review `system()` calls for safety. - Handle `malloc` failures. - Verify `HalMesh_isSameParentMAC` logic for edge cases.
